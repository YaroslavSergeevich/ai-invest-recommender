# Решения и ограничения

- Проверено: 33 теста Vitest; production build; ESLint без предупреждений; Prettier; Docker build и smoke-test nginx/SPA/health/API prefix на localhost:3001; ручная проверка входа, Enter на «Подробнее», действий, чата и адаптации на 390 CSS px без горизонтального overflow.

- Решение: проект создан в отдельном `frontend/`; существующий analytics-source-simulator и пользовательские материалы не изменены.
- Решение: интерфейс следует двум предоставленным скриншотам; банковские виджеты — явные demo-заглушки, карта нарисована CSS, внешние шрифты и изображения не загружаются.
- Решение: React 18 / Router 6 сохранены по заданию; Tailwind 3 использован с исправленным `postcss-selector-parser` через overrides.
- Решение: mock-новости явно обозначены демонстрационными, не содержат выдуманных дат и утверждений о текущих событиях; реальные тексты сервера выводятся без пересказа.
- Решение: mock-assignment выбирает ID из VITE_DEMO_USER_IDS для совместимости с живым legacy push. Agent-overrides mock не исполняет.
- Решение: auto-fallback включается только при 404/Network; Vite маркирует собственную ошибку соединения с backend как PROXY_NETWORK_ERROR. HTTP-ошибки приложения и 15-секундный timeout не подменяются успехом.
- Решение: legacy push сначала запрашивается у настоящего сервера и требует контракт с delivery/notification IDs; фронтенд не придумывает отсутствующие серверные идентификаторы.
- Решение: Telegram-референсы использованы как визуальный ориентир, а не скриншот-фон; интерфейс адаптивный и интерактивный.
- Решение: для ухода используется fetch keepalive, поскольку sendBeacon не позволяет установить обязательные X-* заголовки. Без ACK очередь не очищается.
- Решение: known overlay определяется aria-modal=true или data-telemetry-overlay=true; собственные опросы и выбор причины inline и не блокируют чтение.
- Решение: покрытие текста измеряется DOM Range отдельных слов, а не долей высоты карточки; DOM и тексты прочитанного контента не передаются в события.
- Решение: readiness появляется после раскрытия/действия рекомендации; B decision-followup — только human после подтверждённого save/intend_apply. E13 создаётся после успешной отправки feedback, пропуск не создаёт событие.
- Решение: повторный явный submit сохраняет response_id и повышает version; пользовательский повтор действия создаёт новый operation/action ID, транспортный повтор телеметрии сохраняет event/operation IDs.
- Решение: кнопки действий сохраняют состояние в памяти текущей ленты; API feed не содержит полей saved/intended, поэтому после reload их состояние не выдумывается. Все подтверждённые действия отправляются backend.
- Решение: чат подключён только к реальному legacy API; при отсутствии бэкенда показывает ошибку/повтор вместо вымышленного AI-ответа. История не записывается в storage и телеметрию.
- Решение: в тестах под Node 25 используется реализация Web Storage в памяти, поскольку Node глобальный localStorage конфликтует с jsdom; приложение работает с браузерным localStorage.
- Ограничение: живого Go-backend, analyser и Model B в этом checkout нет; их end-to-end бизнес-контракт и серверная аналитика требуют интеграционного прогона в основном стеке.
- Ограничение: npm audit после исправлений оставляет два moderate предупреждения в React Router 6 (redirect/SSR hydration); исправление требует перехода на Router 7 вопреки заданному стеку. SSR не используется; маршруты Link/Navigate заданы константами. Критических и high предупреждений нет.
- Ограничение: visibility-v1 не распознаёт произвольные сторонние визуальные перекрытия без aria-modal/data-telemetry-overlay. CSS line-clamp учитывается при измерении слов; покрытие не доказывает человеческое прочтение.
- Не реализовано вне заданного объёма: серверное хранение истории чата, пагинация без серверного контракта, логин с паролем, регистрация, админка, WebSocket, PWA, тёмная тема, PDF-экспорт.

- Корректировка: один parseAssignmentSeed преобразует строку query в number/null; невалидный seed блокируется до E01 и assignment, хранение исходной строки сохранено.
- Корректировка: опросы привязаны к актуальной паре delivery_id/recommendation_id и подписаны названием рекомендации; новая выдача сбрасывает выбор и eligible, поздние результаты старой выдачи игнорируются.
- Оценочная конфигурация: .env.evaluation и существующие Docker build-args отключают mock при сборке; готовность collector и полная приёмка метрик требуют отдельной интеграционной проверки.
- Проверка корректировок: 32 целевых / 44 всех теста проходят; TypeScript, ESLint и Prettier проходят. Образ alpha-hack-frontend:evaluation пересобран с VITE_USE_MOCK=false; браузер показал ошибку API без company-context/feed-ready/MOCK. Сохранность очереди без ACK проверена модульно; интеграционная проверка collector в настоящем браузере ожидается. Полная приёмка метрик не выполнялась.
